Alerts - Help

When one of the selected system events occurs, an alert is generated and sent to the configured destination(s).

Globally Enable Platform Event Filtering

Global control for enabling or disabling platform event filtering. When filtering is globally disabled through this setting, alerts will not be sent. This can be used to prevent sending alerts until you have fully specified your desired alerting policies.

Log Event For Filter Action

When a filter match is made, and an action is taken, an event is added to the system event log.

Select the events that will trigger alerts

Select one or more system events that will trigger an Alert. Clearing all events disables Alerts. These events correspond to the IPMI preconfigured Platform Event Filters.

Alert Destinations

Alert destinations can be one of two types:

  • SNMP Trap (can be IPv4 or IPv6 Address)
  • Email (requires Alert Email to be configured)

Actions
Check All

Check all events to generate Alerts.

Clear All

Uncheck all events so no Alerts will be generated.

Save

Click 'Save' to save any changes made.

Send Test Alert

To test whether an alert will reach its destination, configure at least one destination. Then click 'Send Test Alerts' to send a simple test alert to the destination(s).

SNMP Server

Provide SNMP Server option to set.

Enable SNMP

You could Enable/Disable SNMP.

Enable SNMP V1 V2C

You could Enable/Disable SNMP V1/V2C.

Read-Only Community String

SNMP Read-Only Community strings are used only by devices which support SNMPv1 and SNMPv2c protocol.

The maximum length is 32.

Read-Write Community String

SNMP Read-Write Community strings are used only by devices which support SNMPv1 and SNMPv2c protocol.

The maximum length is 32.

NOTE: SNMP Read-Only Community strings and Read-Write Community strings can't be the same value.

NOTE: Can set the configuration of SNMPv3 for each user in "Users" page.

Actions
Save

Click 'Save' to save any changes made on SNMP Server.

SNMP Trap

Provide v1/v2c/v3 protocol option to set.

Community String

SNMP Community strings are used only by devices which support SNMPv1 and SNMPv2c protocol.

SNMPv3 uses username/password authentication, along with an encryption key.

The maximum length is 18.

LAN Channel

SNMPv3 uses current acvite LAN Channel. It could be modified in "IPv4 Network/IPv6 Network" configuration webpage.

User name

The maximum length is 10.

Authentication protocol

The Authentication Protocol for SNMPv3 Trap.

  • MD5
  • SHA

Authentication passphrase

The passphrase's length needs to be set between 8 and 12.

Security level

The Security Level for SNMPv3 Trap.

  • authNoPriv : Communication with authentication and without privacy.
  • authPriv : Communication with authentication and privacy.

Privacy protocol

The Privacy Protocol for SNMPv3 Trap.

  • AES

Privacy passphrase

The passphrase's length needs to be set between 8 and 12.

Actions
Save

Click 'Save' to save any changes made on SNMP Trap.
